Privacy Policy

Last updated 13 November 2026

Personal Bank Overview is privately operated by the account holder for their own non-commercial use. For privacy questions, use the application's data protection contact in Enable Banking's consent interface.

What the application processes

Through Enable Banking, the application reads booked euro transactions and balances from the owner's authorized ABN AMRO and ING payment accounts. It uses these data for local recordkeeping and personal financial summaries. Provider responses may include account numbers, counterparty details and descriptions. The application handles the responses in memory and does not persist those fields or raw responses.

The local database retains bank labels, hashed account and booking references, temporary provider account IDs, consent session IDs and expiry dates, booking dates and amounts, balance amounts and types, available balance reference dates, and synchronization dates and requested date ranges.

Authorization and local storage

The owner authenticates with the bank. The application does not collect or store bank passwords, PINs or one-time bank authentication codes. It validates the local authorization callback and exchanges the authorization code with Enable Banking. API calls use HTTPS and short-lived tokens signed with a local RSA key. The private key is passphrase-encrypted. The passphrase is entered interactively and is not saved.

The SQLite database and application configuration are stored in the owner's Windows profile, normally under %LOCALAPPDATA%\Bankoverzicht. The database itself is unencrypted. Protection on disk depends on Windows access controls and any disk encryption enabled by the owner.

When data may be shared

The bank and Enable Banking process information to authorize and provide account access under their own privacy notices. See the Enable Banking Privacy Notice.

The application previews a report and writes it to the owner's chosen location after explicit confirmation. A default report contains monthly totals, booking counts and synchronization and connection status per account. The owner can add balances or individual booking dates and amounts. If the owner saves the report in a synced folder or uploads it to Google Drive, Google may receive a copy. If the owner uses a report with ChatGPT or the optional local Codex tool, the report contents may be sent to OpenAI. The application itself has no automatic cloud upload or scheduled sharing.

Retention and removal

Local history has no automatic expiry. The owner can end the connection, check revocation with the bank and delete the local history. Ending access leaves existing history on disk. Exported reports, backups and copies in other services must be removed separately.
